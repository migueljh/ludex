# D14 Additive Learnset Inheritance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Resolve D14 by making form inheritance the deduplicated union of the form's own evolutionary branch and its base-species branch.

**Architecture:** `inheritanceChain` remains the only source of ancestry for `extractLearnsets`, but will walk two independent branches into one ordered, deduplicated list: own form/pre-evolutions first, then base species/pre-evolutions. Existing extraction, method parsing, generation filtering and upsert loading remain unchanged.

**Tech Stack:** Node.js 22, TypeScript 5.7, Vitest 2.1.8, `pokemon-showdown@0.11.10`, PostgreSQL 16.

## Global Constraints

- The fix is additive, never `own.prevo || own.baseSpecies`.
- For every species and generation, the previous move set must remain a subset of the new move set.
- Gen 6 baseline is 834 Pokémon, 618 moves and 62,198 learnsets.
- Gen 9 baseline is 874 Pokémon, 685 moves and 65,624 learnsets.
- The four gen 6 Gourgeist forms currently have 66 learnsets each and may not lose any.
- Re-seeding is upsert-only and must run against the populated database.
- Create and verify `/tmp/antes-d14.dump` before re-seeding.
- Use `127.0.0.1:15432`; never stop or remove containers.
- Ignore `.worktrees/`; stage and commit only explicit paths.
